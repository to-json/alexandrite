# M0: Where things stood

Before the Go-parity push (2026-10-01), Alexandrite was a working v0 compiler built to pass the Project Euler acceptance suite (ACCEPTANCE.md A1–A7).

## What exists

- **Front end:** lexer, parser (braces-only, Ruby-flavored), checker with per-instance type inference and monomorphization, purity checking, and a small prover that removes overflow and index checks it can prove unnecessary.
- **Backends, all from one low-level IR:**
  - C via clang, for release builds (`alx build --release`); within about 1x of hand-written Rust on the benchmarks.
  - A Cranelift JIT behind `alx run`: about 2 ms from edit to answer on small programs.
  - A Rust "oracle" backend, compiled by rustc in CI to cross-check every program.
  - WebAssembly, compiled in the browser: the playground on the website.
- **Language:** Int (64-bit, overflow panics; `promote` and `wrap` modes), Float, Bool, Str, arrays, tuples, value structs with keyword construction, ranges, Enumerable chains fused into single loops, generators (`Enumerator.new`), `pmap`, `try` on fallible calls, `format` with Go's verbs, `require`d libraries.

## Benchmarks at this point

| program | alx release | Go | Rust | edit-to-answer: `alx run` vs `go run` |
|---|---|---|---|---|
| n-body, 1M steps | 30.1 ms | 34.8 ms | 31.6 ms | 69 ms vs 229 ms |
| Project Euler (12 problems) | 1.1–1.4x faster than prebuilt Go, mostly startup; even with hand-optimized Go on the work itself | | | 7.5–92x faster |

## What changed in direction

Go became the reference for capabilities and semantics, Ruby the reference for syntax feel. Every divergence between them was decided up front with the user (GO-VS-RUBY.md). The rest of this site follows the milestones in the roadmap.
