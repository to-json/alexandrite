# M1: Numbers

Go's integer types, exact constants and bit operations, on every backend: the JIT behind `alx run`, clang debug and release, the Rust oracle, and the browser. The test program `acceptance/cases/ints.alx` is a line-for-line port of a Go program, and all five backends print exactly what Go prints.

## What you can write now

```ruby
BIG = 1 << 100                # constants are exact: no overflow until used
SHIFTED = BIG >> 98           # 4
KB: U32 = 1024                # a typed constant
puts 0.1 + 0.2                # 0.3: folded exactly, as in Go

a: U8 = 200
puts a +% 56                  # 0: wrapping arithmetic
puts a + 56                   # panics: overflow (U8) at file:line:col
puts ^a                       # 55: complement
x = 0xff_ff
puts x & 0x0f0f, x &^ 0xff    # bit operations, Go's and-not
puts 1 << n                   # 0 once n >= 64, as in Go

u: U64 = 18_446_744_073_709_551_615
puts u / 3                    # unsigned division, comparison, printing
puts 300.as_u8                # 44: truncates, like Go's uint8(300)
puts 300.to_u8                # panics: the value doesn't fit U8
puts format("%x %o %b %c", 255, 8, 5, 9731)   # ff 10 101 ☃

struct Pix { r: U8, g: U8, b: U8, a: U8 }     # 4 bytes in memory
h: U32 = 2166136261           # FNV-1a: wrapping multiply where it's meant
"go".bytes.each { h = (h ^ it.as_u32) *% 16777619 }
```

## What was built

- **Types:** `I8 I16 I32 I64 U8 U16 U32 U64`, with `Int` = I64, `Byte` = U8 and `Rune` = I32. In registers every integer is a 64-bit value (sign- or zero-extended); in arrays and structs each takes its own width, so `[U8]` is a byte buffer.
- **Literals:** `0x`, `0o`, `0b`, underscores, and integers of any size as constants.
- **Constants (Go's rules):** literals and `NAME = expr` definitions are exact (big integers, exact rationals) and take a type only where they're used; one that doesn't fit is a compile error at that point. Typed constants (`KB: U32 = 1024`) behave like values of their type.
- **Operators:** `& | ^ &^ << >>`, unary `^`, wrapping `+% -% *%`, and compound forms (`&=`, `<<=`, `+%=`, ...).
- **Overflow:** checked per type; a panic names the type and the source position; under `try` it becomes an error.
- **Conversions:** `x.to_u8` (checked), `x.as_u8` (truncates); Float → integer via `to_*`; `to_f` from any integer (unsigned for U64).
- **Formatting:** `%d` for any integer, `%x %X %o %b %c`.
- **Typed locals:** `x: U8 = 200`.

The lowering expands Go's semantics into a handful of primitive operations (bitwise ops, unsigned compare and divide, a narrow-width wrap), so each backend only had to implement those.

## Tests

- `ints.alx`: 39 lines, identical to Go's output on all five backends.
- Three failure cases: a runtime overflow (abort, message names `U8` and the line), a constant that doesn't fit (`constant 300 overflows U8`), mismatched types (`mismatched types U8 and I32 for '+'`, with a hint to convert).
- Acceptance: **89 of 89 checks pass**, including the Project Euler and n-body cases; release performance is unchanged (n-body 0.96x of Rust).

## Not yet

- `sum` over sized integers (Int and Float only so far); ranges of sized integers.
- `**` on sized integers (Go has no `**` at all; Int keeps it).
- In `#![overflow(promote)]` files, an integer constant above 64 bits is still a compile error rather than a bignum.
