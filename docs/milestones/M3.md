# M3: Collections and absence

Go's collection model with Ruby's spelling, on all five backends. The test `acceptance/cases/collections.alx` covers it, and every backend prints the same 65 lines.

## What you can write now

```ruby
a = [1, 2, 3, 4, 5]          # [Int]: a slice
b = a                        # shares storage: b[0] = 10 changes a[0]
mid = a[1..3]                # reslice (inclusive; a[1...3] exclusive; a[2..], a[...2])
c = a.dup                    # own storage
copy(dst, a)                 # Go's copy: min(len), memmove semantics

f: [Int; 3] = [1, 2, 3]      # fixed array: a value
g = f                        # a copy; so is passing it to a def
grid: [[Int; 3]; 2] = [[0; 3]; 2]
z: [Int; N] = [0; N]         # N is a constant

s = "héllo, 世界"
s.size                        # 14: bytes, as in Go
s[1]                          # 195: a Byte
s.runes.count                 # 9 code points
s[0..2] + "!"                 # "hé!"
Str.from_bytes(buf)

ages = {"ada" => 36, "bob" => 25}    # Map[Str, Int], insertion-ordered
ages["cy"] = 41
if age = ages["bob"] { ... }         # m[k] is an Int?
counts[w] += 1                       # a missing key reads as 0 (Go)
ages.delete("bob")                   # Int?
for k, v in counts { ... }           # and every pipeline method: counts.select { |k, v| ... }
puts ages                            # map[ada:36 bob:25 cy:41]

def find_even(xs: [Int]) -> Int? {
  for x in xs { return x if x.even? }
  none
}
puts u.boss || "nobody"              # || unwraps, ?. chains
xs.find { it > 4 }                   # Int?
```

## What was built

### Slices and fixed arrays (C1)

- **`[T]` is a Go slice:** a `{ptr, len, cap}` header over shared storage. Assigning or passing one copies the header, so writes are visible through every alias. `<<` appends in place while there is capacity and reallocates otherwise, the same as Go's `append`.
- **Reslicing:** `a[lo..hi]`, `a[lo...hi]` and either end left open. Bounds are checked: `slice bounds out of range at file:line:col`.
  - A subslice has **no spare capacity**, so appending to it copies rather than overwriting the parent's next element (D6). This is the one deliberate departure from Go here.
- **`[T; N]` is a value:** assignment, argument passing, struct fields, map values and option payloads all copy it, nested fixed arrays included. A slice taken from a fixed array views its storage, as in Go.
  - `N` is any integer constant expression.
  - A literal of the right length becomes a fixed array where one is expected. A wrong length is a compile error: `2 elements where [Int; 3] needs 3`.
  - `<<` and `pop` are rejected; every read-only method works.
- **`[v; n]`** makes `n` copies. When `v` holds storage, it is evaluated once per element, so rows are independent (D7).
- **`dup`, `copy(dst, src)`.**

### Strings are bytes (S3)

- `size` is in bytes and `s[i]` is a `Byte` (bounds-checked). `s[lo..hi]` is a byte substring.
- `bytes` yields `Byte`s; `runes` yields `Rune`s (U+FFFD for a bad lead byte); `chars` still yields one-character strings.
- `Str + Str` concatenates. `Str.from_bytes([Byte])` copies.
- Strings are immutable: `s[i] = b` is an error that points to `bytes` and `Str.from_bytes`.

### Maps (C2)

- **Syntax:**
  - Types: `Map[K, V]`.
  - Literals: `{k => v}`, `{name: v}` (Str keys) and `{}` (types inferred from use, or from a declaration).
  - Struct fields of map type start as empty maps, and `Name.new` with no arguments zero-fills.
- **Operations:**
  - Reads: `m[k]` is `V?`, and `m.fetch(k, default)` gives the default when the key is missing.
  - Writes: `m[k] = v`, and `m[k] op= v` (a missing key reads as V's zero, as in Go).
  - Queries and copies: `key?`, `delete(k)` (returns `V?`), `size`, `empty?`, `keys`, `values`, `dup`.
  - Iteration: `for k, v in m` and every pipeline method over `(k, v)` pairs.
- **Semantics:**
  - Maps are shared, like Go maps.
  - Order is insertion order. Deleting while iterating is fine.
  - `puts` prints Go's `map[k:v ...]` (D8).
  - Keys are integer types, Str or Bool for now.
- **Implementation:** the map is written once, in LIR, rather than five times in five runtimes.
  - The compiler generates `find`/`set`/`delete` functions per key and value type: open addressing over insertion-ordered entry arrays, with a murmur3 finalizer (FNV-1a for strings, and for bignum keys in promote mode via their digits).
  - Every backend sees ordinary functions and arrays.
  - It is quick: 2M upserts and 2M lookups take 0.07 s of CPU in a release build versus 0.11 s for Go's map.

### Absence (C3)

- `T?` everywhere a type goes.
  - Narrowing: `if x = e` and `while x = e`.
  - Operators and methods: `x || default`, `x?.m`, `present?`, `none?`, `unwrap`, `unwrap_or`.
  - Absent values: `none`. A plain `T` is accepted where a `T?` is expected.
  - `if`/`else` and `case` arms mixing `T` and `T?` values join to `T?`.
- `find`/`detect`, `m[k]` and `m.delete(k)` return `T?`. `max`, `min`, `first` and `reduce` still panic on an empty collection, like Go's `slices.Max` (D5).

### Under the hood

- **The Rust oracle's slices:** a slice there is now `Sl<T>`, a window onto `Arc<Mutex<Vec<T>>>`. That gives Go sharing semantics in safe Rust; nested writes go through closures.
- **Value copies:** fixed arrays and anything holding one are copied by `copy_value` at stores, unless the expression already built a fresh value.
- **pe022** changed `it - 64` to `it.to_i - 64`, because `bytes` now yields `Byte`s. Go needs the same conversion.

## Decisions made on the way (logged as D5 to D9)

| # | Call |
|---|---|
| D5 | `max`/`min`/`first`/`reduce` panic on empty; `find`, `m[k]`, `delete` give `T?` |
| D6 | subslices have no spare capacity: `<<` onto one copies (avoids Go's `append` aliasing) |
| D7 | `[v; n]` evaluates a storage-holding fill per element |
| D8 | maps print Go's `map[k:v]` in insertion order; keys are ints, Str, Bool |
| D9 | `copy(dst, src)` is Go's, with memmove semantics |

## Tests

- `collections.alx`: 65 lines, identical on the JIT, clang debug, clang release, ASan/UBSan and the Rust oracle, and in the browser (wasm).
- Negative cases:
  - `collections.bad1` and `collections.bad2` are compile errors: fixed-array length, and pushing onto a fixed array.
  - `collections.oob` is a runtime failure (slice bounds).
- Acceptance: **100 of 100 checks pass.** The browser suite passes 26 of 26.

## Not yet

- **Deferred:**
  - Map keys that are tuples or structs (needs struct equality, M4).
  - `m[k][i] = v` through a map.
  - `==` on arrays and maps.
- **Gaps:**
  - `runes` doesn't replace every invalid sequence with U+FFFD the way Go does (only a bad lead byte).
  - `puts {…}` parses the braces as a block, as in Ruby; bind the map first.
  - A block call inside an `if` or `while` condition needs parentheses: `if x = (xs.find { ... }) { }`.
