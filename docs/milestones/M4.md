# M4: Types

Methods, operators, enums, interfaces, generics and lambdas, on all five backends. The test `acceptance/cases/types.alx` covers them, and every backend prints the same 31 lines.

## What you can write now

```ruby
struct Point {
  x: Float
  y: Float
  def norm -> Float { (x * x + y * y).sqrt }   # fields read bare
  def move!(dx: Float, dy: Float) {             # `!` changes the receiver
    self.x += dx
    self.y += dy
  }
}
p.move!(1.0, 1.0)            # also b.pos.move!(...), ps[1].move!(...)

struct V2 {
  x: Int
  y: Int
  def +(o: V2) -> V2 { ... }
  def <=>(o: V2) -> Int { ... } # gives < <= > >=
  def to_s -> Str { "(#{x}, #{y})" }
}
a == b                        # field by field, no method needed

enum Shape {
  Circle(r: Float)
  Rect(w: Float, h: Float)
  Empty
  def area -> Float {
    case self {               # must cover every variant (or `_`)
      Circle(r) => 3.0 * r * r
      Rect(w, h) => w * h
      Empty => 0.0
    }
  }
}
enum Color { Red, Green, Blue }  # Go's iota: Color.Blue.to_i == 2

interface Named {
  def name -> Str
  def greeting -> Str { "hello, #{name}" }   # default
}
named: [Named] = [Dog.new, Robot.new(id: 7)] # satisfied structurally

struct Stack[T] { items: [T]; def push!(x: T) { self.items << x } }
s = Stack[Int].new           # or inferred: Stack.new(items: ["a"])
def largest[T](xs: [T]) -> T { ... }
def sum_all[N: like Int](xs: [N]) -> N { ... }
def greet[T: Named](x: T) -> Str { ... }

double = ->(x: Int) -> Int { x * 2 }
def make_adder(n: Int) -> (Int) -> Int { ->(x: Int) { x + n } }
ops: [(Int, Int) -> Int] = [->(a, b) { a + b }, ->(a, b) { a * b }]
ops.each { puts it(6, 7) }
```

## What was built

### Methods (F1)

- **Declaration:** a struct or enum body holds `def`s, compiled as functions named `Type.method` with `self` first.
- **Inside a method:**
  - Fields are read bare (`x`). Methods are called bare (`norm`, `move!(...)`).
- **Writes (D10):**
  - Writes to fields must be spelled `self.x = ...`.
  - Assigning to a bare field name is an error, so it can't silently make a shadowing local.
- **`!` methods:** a `!` method gets a one-element slice holding its receiver.
  - The call site passes the place and writes the receiver back.
  - This is Go's pointer receiver, without pointers, and it works through fields and elements (`b.pos.move!`, `ps[1].move!`).
- **Plain methods:** a plain method gets a copy, and assigning to its `self` is an error that suggests `!` (D11).
- **Pushing through places:** `self.items << x` and `grid[i] << x` push through the place: read the header, push, write it back.

### Operators and equality (T4)

- **Operators:** `def + - * / %`, `def ==`, `def <=>` (which gives the four comparisons) and `def []` hook the operators.
- **Default `==`:** without `def ==`, structs, tuples and enums compare field by field (Go's comparable types). A slice or map field makes `==` an error that suggests `def ==` (D13).

### Printing (D14)

Printing follows Go's `%v`:
- Slices print as `[1 2 3]` and structs as `{1 2}`.
- Enums print as `Circle(1)` or `Red`.
- A type's `to_s` is used wherever it's printed, inside slices and maps too (Go's `Stringer`). The checker instantiates every `to_s` reachable from a printed type.

### Enums (T5, T6)

- **Variants:** named or positional fields.
  - Build them with `Shape.Circle(1.0)`, `Shape.Rect(w: 2.0, h: 3.0)` or `Color.Red`.
  - Enums can have methods and can be generic.
- **`case`:** binds payloads (`Circle(r)`, `Rect(w, _)`) and must cover every variant or have `_`. The error names what's missing.
- **Payload-free enums** are Go's `iota` constants: `to_i`, `==`.
- **Representation:** a value holds the tag plus every variant's fields side by side. That costs a little space and needs nothing new from any backend.

### Interfaces (F2, D12)

- **Declaration:** required methods have no body. Default methods have a body and see the concrete `self`.
- **Satisfaction:** a struct or enum satisfies an interface by having the methods, checked with their types where it is converted.
  - Conversion is implicit wherever the interface is wanted: declarations, arguments, slice literals, `<<`.
- **Defaults on concrete values:** default methods work directly on concrete values too (`Dog.new.greeting`).
- **Representation: closed-world sums.**
  - The compiler sees the whole program, so an interface value is a tag plus a slot for each type ever converted to it, and a call dispatches on the tag to each implementor's method instance.
  - No boxing, no vtables, no GC: the representation waits on the memory-model conversation like everything else.

### Generics (T3)

- **Declaration:**
  - Type parameters go on structs, enums and defs: `[T]`, `[K, V]`, with bounds `T: Interface` and `N: like Int`.
  - Bounds are checked when an instance is made.
- **Instances:** each one is a distinct type named `Stack[Int]`, and its methods are checked per instance (monomorphized).
- **Inference (D15):** type arguments come from constructor values, from the declared type (`t: Stack[Str] = Stack.new`), or are spelled out (`Stack[Int].new`).

### Lambdas (D16)

- **Syntax:** `->(x: T) -> R { }`, type `(T) -> R`, called `f(x)` or `f.call(x)`.
  - Parameter types can come from the wanted function type: `apply(->(x) { x - 1 })`.
  - `return` returns from the lambda.
- **Representation:** the same closed-world trick. A function value is a tag plus the captured values of each lambda literal of that type, and every literal becomes its own function.
- **Captures are copies.** Slices and maps still share their storage, so `counts["n"] += 1` inside a lambda is visible outside, but a captured Int counter isn't.
  - This is the one place we differ from Go's by-reference closures. It gets revisited with the memory model.

## Tests

- `types.alx`: 31 lines, identical on the JIT, clang debug and release, ASan/UBSan, the Rust oracle and wasm.
- Negative cases:
  - `types.bad1` is a non-exhaustive `case`.
  - `types.bad2` is a type missing an interface method.
  - `types.bad3` assigns `self` in a non-`!` method.
- Acceptance: **107 of 107 checks pass.** The browser suite passes.

## Not yet

- **Waits on the memory model:**
  - Recursive types (`enum Tree { Node(left: Tree, ...) }`, even through slices).
  - Mutable captured variables.
- **Interfaces:**
  - `!` methods in interfaces (Go's `io.Writer` on a pointer). Needed before porting `io`.
  - Interface methods count as impure, so a `fn` can't call them.
- **Function values:** fallible lambdas, and lambdas compared with `==`.
- **`<=>` and sorting:** `<=>` doesn't feed `sort` yet. Use `max_by`/`min_by`, which now take Int, Float or Str keys.
