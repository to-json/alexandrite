# M5: Errors

Rust-shaped errors in this language's spelling. Errors are values, `~` propagates them, and declared error sets are checked. The test `acceptance/cases/errors.alx` prints the same 15 lines on all five backends.

## What you can write now

```ruby
error ParseError {
  Empty
  BadDigit(at: Int, ch: Str)

  def message -> Str {                 # optional; default prints the value
    case self {
      Empty => "empty input"
      BadDigit(at, ch) => "bad digit `#{ch}` at #{at}"
    }
  }
}

def parse(s: Str) -> ~Int<ParseError | ArithError> {
  fail ParseError.Empty if s.size == 0
  n = 0
  for c in s.chars {
    ...
    n = ~(n * 10 + d)                  # overflow becomes an ArithError
  }
  n
}

def sum_all(xs: [Str]) -> ~Int {       # set inferred
  total = 0
  for x in xs { total += ~parse(x) }   # propagate
  total
}

def checked(s: Str) -> ~Int<Error> {   # open: anything
  v = ~parse(s)
  fail "too big: #{v}" if v > 1000     # a Failure
  v
}

r = sum_all(["12", "x3"])              # no `~`: a ~Int value
r.ok?  r.unwrap_or(-1)  r.ok  r.err  r.unwrap
v = parse("4z").rescue { |e| -1 }
case e {
  Empty => ...
  BadDigit(at, _) => ...
  Overflow => ...                      # a builtin ArithError variant
  Failure => ...                       # a whole error type
  _ => ...
}
e.wrap("reading config")               # "reading config: empty input"
names = ~File.read("names.txt")        # at the top level: print and exit 1
```

## What was built

- **Spelling (E1–E4):**
  - **Types:** `~T`, `~T<E | F>` and `~T<Error>`, with `< >` reserved for error sets.
  - **Propagation:** prefix `~` attaches to the next call, so `~load(p).~section("db")` propagates both. `~(a * b)` checks arithmetic, and `~r` propagates a held Result.
  - **Old syntax:** `try` and `-> T!` are gone, with errors that show the new spelling.
- **`error` declarations:** these are enums, so they get variants, fields, methods and `case`. `fail` takes an error value, or a Str (which becomes `Failure.Msg`).
- **Error sets (D20):**
  - The checker tracks what each function can fail with: its `fail`s, the `~`s on callees (whose sets were inferred the same way), `~(arith)` and `File.read`.
  - A declared `~T<...>` that misses one is an error naming the type: ``can fail with ArithError, which its `~T<ParseError>` doesn't list``.
- **Results as values (D21):**
  - Without `~`, a fallible call is a `~T`, at the top level too, so there is no implicit exit any more.
  - Methods: `ok`, `err`, `ok?`, `err?`, `unwrap`, `unwrap_or` and `rescue { |e| ... }`.
- **Errors:**
  - `message` and `wrap`; they print as their message.
  - `case` matches variants of any error type unqualified, or a type by name. It needs `_`, because an `Error` is open.
- **Uncaught errors (D19):** `error: <message> (<file:line:col>)` on stderr, then exit 1, after running any `defer`s on the way out.

### Under the hood

- **Errors as values in the IR:**
  - A fallible function returns an ordinary tuple: ok, value and an `Error`.
  - The `Error` is one sum over every error type in the program: a type tag, the location, the wrap context, then each type's value (D17).
  - `~` is a test and an early return, after running the `defer` cleanup. The error message comes from one generated function.
- **Builtin failures become plain checks:**
  - Overflow under `~(...)` is a bit test, for example `((a ^ r) & (b ^ r)) < 0` for addition.
  - `File.read` checks the file's status first.
  - So the backends needed only three new primitives (a dynamic `die`, a file-status check and a file read), and the old per-backend error calling convention became dead code.
  - A Sonnet agent added the primitives, and another removed the dead code.
- **`pmap`:** a block using `~` returns a Result per element, and the first failing element's error propagates once the workers finish.
- **Existing programs:** `pe014` and `pe022` moved to `~`.

## Tests

- `errors.alx`: 15 lines, identical on the JIT, clang debug and release, ASan/UBSan, the Rust oracle and wasm.
- Negative cases:
  - `errors.bad1` is an unlisted error type.
  - `errors.bad2` uses `~` in a non-fallible def.
  - `errors.bad3` uses the old `-> T!`.
  - `errors.die` is an uncaught error: exit 1, with the message and location.
- Acceptance: **115 of 115 checks pass.**

## Not yet

- **Matching:** exhaustive `case` over a closed error set (it needs `_` for now). Qualified patterns (`IoError.NotFound(p)`).
- **Error information:** `e.cause`, and stack traces or propagation paths (the location is where it was raised).
- **Lambdas:** `~` and `fail` inside lambdas.
- **Tooling:** warnings for unused Results (M8, with the other warnings).
