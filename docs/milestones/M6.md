# M6: Packages and refinements

Go's directory packages with an explicit `pub`, Go modules (minus downloading), and Ruby's refinements, lexically scoped. The test programs `packages.alx` and `refinements.alx` print the same output on all five backends, and the `modtest` fixture checks module resolution.

## What you can write now

```ruby
# pkgs/geom/point.alx  (every .alx file in pkgs/geom/ is package `geom`)
pub struct Point {
  x: Float
  y: Float
  pub def norm -> Float { (x * x + y * y).sqrt }
  def secret -> Float { 42.0 }          # not callable outside geom
}
pub def dist(a: Point, b: Point) -> Float { ... }
pub refine Units for Float {
  pub def cm -> Float { self * 100.0 }
}

# main.alx
import "pkgs/geom"
import sh "pkgs/shapes"                  # an alias

p = geom.Point.new(x: 3.0, y: 4.0)
puts geom.dist(p, geom.origin)
s = geom.Stack[Int].new                  # generic types across packages
a = ~sh.circle(0.0, 0.0, 1.0)            # errors across packages
pt: geom.Point = geom.origin             # qualified types
using geom.Units
puts 2.5.cm

refine Shouty for Str {
  def shout -> Str { self + "!" }
}
def quiet(s: Str) -> Str { s }           # no `shout` here
using Shouty                             # from here to the end of the file
puts "hi".shout
def scoped -> Float {
  if c {
    using Metric                         # only inside this block
    ...
  }
}
```

## What was built

### Packages (P1, D22, D23)

- **Imports:** `import "path"` loads a package, which is every `.alx` file in that directory except `*_test.alx`.
  - Paths resolve under the module root (the nearest directory up with an `alx.mod`), or through a required module.
  - Packages import packages, and cycles are an error naming the chain.
  - `require` is gone, with an error pointing at `import`.
- **Naming:** a package's declarations are qualified by its path.
  - Inside the package, names resolve package-first.
  - Outside, they're reached as `alias.name`, `alias.Type` and `alias.CONST`, in types too (`geom.Point`, `geom.Stack[Int]`).
  - The callee's signature is resolved in the callee's package.
- **Visibility:** `pub` on a def, struct, enum, error, interface, constant, refinement or method. Using anything else from outside is an error that names it.
- **Separate compilation (A6's library reuse):**
  - Packages whose exports are plain typed defs still compile to a cached object behind a header, so `lib/primes` builds once.
  - Packages whose layout depends on the whole program (interfaces, errors, generics) are checked with the program.
  - `alx run` always JIT-compiles the whole program from source.

### Modules (P6, D25), built by a Sonnet agent

- **`alx.mod` grammar:** `module`, `require`, `replace` (also in `( ... )` blocks).
- **Dependency imports:** they resolve through the longest required module prefix. A module's directory is its `replace` target, or `$ALX_MODCACHE/<module>@<version>` (default `~/.alx/mod`).
- **Version selection:** Go's minimal version selection, which picks the highest version any module's `alx.mod` requires. The fixture proves `dep2 v1.2.0` wins over the main module's `v1.0.0`.
- **Not yet:** downloading and `alx.sum`. A module missing from the cache is an error that says so.

### Refinements (D24)

- **Declaration:** `refine Name for Type { defs }` adds methods to any type, builtins included. Several blocks with the same name accumulate (`Shouty for Str`, `Shouty for Int`).
- **Activation:** `using Name` activates them for the rest of the enclosing block, or for the rest of the file at the top level (including the defs below it).
  - Refinements are lexical: a def declared above the `using` doesn't see them.
  - An active refinement wins over the type's own methods.
  - A refinement's methods see each other.

## Tests

- `packages.alx`:
  - Two packages, one importing the other, with private and `pub` members.
  - A generic struct, a `!` method, an error type and a refinement, all used across the boundary.
- `refinements.alx`: file-level and block-level `using`, precedence over the type's own methods, and a def above the `using` that doesn't see it.
- Negative cases:
  - `packages.bad1` and `packages.bad2` use a private def and a private method.
  - `packages.bad3` imports a missing package.
  - `refinements.bad1` calls a refined method without `using`.
- Module checks: require, replace and MVS output; an unrequired import; a module missing from the cache.
- Acceptance: **130 of 130 checks pass.**
