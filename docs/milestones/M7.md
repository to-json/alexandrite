# M7: Concurrency

Go's model with this language's spelling: tasks, channels and `select`. A panic ends only its own task. The test `acceptance/cases/concurrency.alx` prints the same 13 lines on the JIT, clang debug, release, ASan/UBSan and the Rust oracle.

## What you can write now

```ruby
def produce(ch: Chan[Int], n: Int) {
  (1..n).each { ch << it }
  ch.close
}

nums = Chan[Int].new(4)          # buffered
squares = Chan[Int].new          # unbuffered: a rendezvous
spawn produce(nums, 10)
sq = spawn {
  for v in nums { squares << v * v }
  squares.close
  "squarer done"
}
total = 0
for s in squares { total += s }  # until closed
puts sq.wait.unwrap              # wait gives a ~T

workers = (1..4).map { |w| spawn { ... } }.to_a
handled = workers.sum { it.wait.unwrap }

r = (spawn { [1, 2, 3][7] }).wait   # a panic ends only its task
r.ok?                            # false; r.err is a TaskError

t = spawn { ~check(-5) }         # a body's errors come back through wait

select {
  when v = a.recv => puts "a: #{v}"   # v is a T? (none once closed)
  when out.send(42) => puts "sent"
  else => puts "nothing ready"
}
```

## What was built

- **Language:**
  - `spawn { body }` / `spawn f(x)` gives a `Task[T]`. The body gets copies of the locals it uses, and slices, maps and channels inside still share storage.
  - `t.wait` is a `~T`. It holds the body's value, the body's error if it used `~`, or a `TaskError` if it panicked. It can be waited on again.
  - Channels: `Chan[T].new(cap)` with `send`/`<<`, `recv` (a `T?`), `close`, `size`, and Enumerable (`for v in ch`, `ch.sum`).
  - `select { when v = ch.recv => ...; when ch.recv => ...; when ch.send(x) => ...; else => ... }`.
- **Design (D26–D28):**
  - **Panic isolation (F6):** a runtime panic in a task (bounds, overflow, `unwrap`, send on a closed channel) ends that task, and `wait` reports it. The main thread still aborts.
  - **Deadlock detection:** "all tasks are asleep: deadlock" when every live thread is blocked.
  - **Browser:** the playground refuses concurrency at compile time, since it has no threads.
- **IR:** handle types `Task`/`Chan` and operations `Spawn`, `Wait`, `ChanSend`, `ChanRecv`, `ChanClose`, `Select`, `ChanNew` and `ChanLen`, specified in `lir.rs`. `spawn` reuses `pmap`'s worker machinery, with the captured copies as the worker's input.
- **Backends, built by Sonnet agents in parallel against that spec:**
  - **C runtime** (pthreads; also used by the JIT through shims):
    - Tasks run on detached threads; the result goes into a heap buffer that `wait` reads.
    - Channels are ring buffers, with a real rendezvous for unbuffered ones.
    - `select` shuffles its cases and makes non-blocking attempts. Blocked selects register as waiting senders or receivers, so two selects can meet.
    - A task records a panic and `longjmp`s back to its entry instead of aborting.
    - The runtime has its own test (`compiler/runtime/tests/tasks_test.c`), clean under ASan and TSan.
  - **Rust oracle:** `Task<T>`/`Chan<T>` in safe Rust (`Arc`/`Mutex`/`Condvar`). A task's panic unwinds quietly into its result.
  - **wasm:** a compile error.

## Tests

- `concurrency.alx`:
  - a three-stage pipeline (buffered and unbuffered channels);
  - a worker pool of 4 over 100 jobs;
  - a panicking task and a failing task, both reported through `wait`;
  - `select` with a ready case, with `else`, and on a closed channel;
  - a `select` send.
- Negative: `concurrency.deadlock` (a receive nobody will ever send to).
- The browser test checks that concurrency is refused cleanly.
- Acceptance: **137 of 137 checks pass.**

## Not yet

- **Scheduling:** an M:N scheduler (goroutine-cheap tasks). Tasks are OS threads with 8 MB stacks, so thousands are fine and millions aren't.
- **Missing pieces:**
  - `Context` (cancellation and deadlines) and timers (`time.After`). These come with the standard library port, as alx packages on top of channels.
  - Shared-memory synchronization beyond channels (`Mutex`, `WaitGroup`, atomics), and a race detector.
  - Concurrency in the browser.
- **Known gap:** a `select` waiting to receive that commits to another case can leave an unbuffered sender in a send-`select` waiting for the next receiver. That is slightly looser than Go.
- **Ownership:** data races on shared slices and maps aren't prevented. That belongs to the memory-model conversation.
