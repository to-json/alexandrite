# M8: Tooling

The everyday tools Go users expect: warnings, a formatter and a test runner. With this milestone the Go-parity push is complete. Most of the tooling was built by Sonnet agents working in parallel worktrees against specs from the decisions log.

## Warnings (P3, D29)

```
warning: `unused` is assigned but never used
  --> calc.alx:3:3
   |
  3|   unused = n * 2
   |   ^
   = use it, or name it `_` or `_name`
warning: `pk` is imported but not used
```

- **What warns:** locals that are assigned but never read, and imports nothing refers to. A leading `_` silences one.
- **When they're errors:** under `--strict` and in `alx test`.
- **Not included:** parameters don't warn (Go doesn't either).

## `alx fmt` (P4, D30)

```
alx fmt file.alx dir/          # rewrite in place
alx fmt --check acceptance/cases   # list files that would change; exit 1 if any
alx fmt - < in.alx > out.alx
```

- **How it works:** it uses the compiler's own lexer and rebuilds only the whitespace between tokens.
  - Every result is re-lexed and compared token by token with the input, so formatting can't change meaning. If anything differs, it writes nothing.
  - Strings, interpolation, heredocs and `ƒ` are copied byte-for-byte.
- **The style:**
  - Two-space indentation by bracket nesting.
  - Spaces around binary operators. `{ x }` blocks, but tight `{k => v}` map literals.
  - At most one blank line. Line breaks are never added or removed, since newlines end statements.
  - Trailing comments are aligned in runs, as gofmt does.
- **Tests:**
  - Every acceptance case is a fixed point.
  - The suite checks `alx fmt --check` over the cases.
  - `cargo test` runs the formatter's own tests: idempotence, token equality and style cases.

## `alx test` (P5, D31)

```ruby
# calc_test.alx, next to calc.alx (same package: private defs are visible)
test "adds" {
  assert_eq add(2, 3), 5
}
test "parses" {
  n = ~parse("42")          # an error reaching the top fails the test
  assert n > 0
}
bench "add" {
  add(1, 2)
}
example "greeting" {
  puts greet("ada")
} outputs "hello ada"
```

```
$ alx test
=== RUN   adds
--- PASS: adds (0.00s)
=== RUN   parses
--- FAIL: parses (0.00s)
    assertion failed: n > 0 at calc_test.alx:7:3
PASS / FAIL
ok     . 0.012s
```

- **Running:**
  - Each test, example and benchmark runs as its own task (M7), so a failing assertion, a panic or an error fails that test only.
  - Flags: `-run NAME` and `-bench NAME` filter by substring, `-benchtime 2s` sets the benchmark time, and `--release` uses the C backend.
- **Output:** Go-style, and the exit status is 1 on any failure.
- **Benchmarks** grow their iteration count the way Go's do and report ns/op.
- **Examples** capture what the body prints and compare it with `outputs`.
- **New runtime primitives**, added to every backend:
  - a dynamic panic message, task-aware (so a failure ends only its test);
  - exit with a status code;
  - a monotonic clock, exposed as `Time.now_ns`;
  - stdout capture.

## Fixed on the way

- **Value-less `if`/`else` in C:** an `if x = opt { f() } else { g() }` whose branches end in calls that return nothing used to generate invalid C. It now lowers to statements. The test-runner agent found it, and `syntax.alx` has a regression case.

## Tests

- `alx test` checks:
  - a passing package (tests, examples, a benchmark, an imported helper package);
  - a failing one (assert, `assert_eq` on Int and Str, an error, a panic, a wrong example, then a passing test), with exit 1;
  - `-run`, `-bench`, `-benchtime`, `--release`;
  - a misplaced `test` block.
- `asserts.alx` checks assertion messages inside tasks on every backend.
- Warning and `--strict` checks. The formatter check.
- Acceptance: **153 of 153 checks pass.**

## Not yet

- **`alx test`:**
  - Table-driven helpers and subtests (`t.Run`).
  - Coverage, fuzzing and parallel tests.
- **Warnings:** unused-result warnings for `~T` values (E4), and unused private defs.
- **Formatter:** reflowing long lines (on purpose: line breaks are significant).
