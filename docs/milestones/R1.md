# R1: Scoped regions

The first step of the memory model (decision R1: regions by default, reference counts for what escapes). Until now nothing was ever freed. Now every function call and every loop iteration gets a region of its own, freed when it ends, and the compiler decides where each allocation lives. Nothing changes in the source code (R2: ownership is invisible).

## What it buys

| program (release build) | peak memory before | after | time before | after |
|---|---|---|---|---|
| `mem/calls.alx`: 20,000 calls that each build 50 strings | 685 MB | **1 MB** | 0.085 s | **0.043 s** |
| `mem/loops.alx`: 600,000 loop iterations that build strings (`while`, `each`, `for`) | 78 MB | **2 MB** | | |

The calls program runs twice as fast because it touches far less memory. The acceptance suite's speed budgets all still hold.

## How it works

- **Three places an allocation can go:**
  - **The call's frame region**, entered on the way in and freed on every way out: falling off the end, `return`, errors, and through `defer`.
  - **The caller's region**, for anything that can become the result. The caller chooses which region is current at the call, so this is passing the destination region dynamically.
  - **The program region** (never freed), for anything that can outlive both: whatever is stored into a parameter's storage, channels, tasks, generators, and unknown callees.
- **Loop iterations.** `while`, `loop`, `each` and `for` bodies get an iteration region that is renewed every iteration, and also freed on `next`, `break` and `return`. Iteration regions are only used when something allocated inside can't be carried to a later iteration.
  - A variable assigned in one iteration and read in the next keeps its value (`last = "middle"` in an `if`), so such values stay in the frame.
- **Escape analysis** (`compiler/src/regions.rs`):
  - Each function is a graph of locals, allocation sites, the result and the program region. Assignment is aliasing, which is symmetric: both names see what's stored through either. Storing a value into a container is one-way.
  - Each site lives in the strongest place it can reach.
  - Calls use the callee's summary (does parameter i reach the result, or something longer-lived?), solved to a fixpoint over the whole program, recursion included.
  - Values with no storage (Ints, Bools) carry no aliases, except Ints in promote mode, which are bignums.
  - Whatever the analysis doesn't understand is treated as escaping, so it can keep memory too long but can't free it early.
- **Errors leaving a function** are deep-copied into the caller's region, since errors are rare.
- **Top-level error messages** are built before the frame is freed.
- **Runtime** (built by a Sonnet agent):
  - A region is a list of 1 MB chunks plus large blocks. Switching regions swaps the existing inline bump pointer, so allocation stays a pointer bump.
  - Freed chunks go to a per-thread free list (at most 4 MB kept).
  - Under ASan, chunks are really freed, so any too-early free crashes the sanitizer row of the acceptance suite. That row caught two real bugs while this was being built: one-way aliasing, and bignums in promote mode.
  - `ALX_MEMSTATS=1` prints peak and final memory. `ALX_NO_REGIONS=1` turns the analysis off for comparison.
- **Rust oracle and wasm:** regions are no-ops. Rust owns its memory, and the browser runs short programs.

## Tests

- `regions.alx` exercises every way a value leaves a call:
  - returned, nested in a struct, stored into a parameter or through a parameter's field;
  - a view or element of an argument;
  - an error, a value stored into a parameter map, a lambda capture, an array grown and returned;
  - a channel and a task, and recursion.

  It gives identical output on all backends and is ASan-clean.
- Bounded-memory checks: `mem/calls.alx` and `mem/loops.alx` must peak at 8 MB or less.
- Acceptance: **159 of 159 checks pass.** Every case's ASan row now runs with regions freeing for real.

## Not yet (next milestones)

- **R2:** values stored into long-lived places still go to the program region and stay there. This affects a map that lives for the whole program, a field of a parameter, or a value sent on a channel.
- **R3** reference-counts those, so replacing `cache[k]` frees the old value.
- **Lambdas, generators and task bodies** allocate in whatever region is current when they run. That's safe, but they don't free their own temporaries yet.
