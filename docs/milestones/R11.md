# R11: Package-level state

Decision R11 (port-issues #51): a package may hold mutable state, but only behind an `Atomic[T]` or a `Mutex[T]`. Go's package `var`s that std needed (log's standard logger, rand's global source, signal's handler table, zip's compressor registry, rpc's DefaultServer) now have a home. Everything else at the top level stays constant.

## Atomic[T] for any T

```ruby
struct Conf { name: Str; tags: [Str] }
conf = Atomic.new(Conf.new(name: "base", tags: []))
c = conf.load                  # a copy: changing it leaves the atomic alone
conf.store(Conf.new(name: "next", tags: ["x"]))
old = conf.swap(Conf.new(name: "z", tags: []))
ok = names.compare_and_swap("hello", "world")   # T must support ==
```

- **`load`** returns a copy (deep, as a `lock` block's value is).
- **`store(v)`, `swap(v)`, `compare_and_swap(old, new)`** replace the value as a whole. The arguments are evaluated first, outside the lock.
- **`add(n)`** stays Int-only.
- **Int and Bool atomics are unchanged:** a hardware cell, lock-free.
- **Anything else sits behind a lock,** in a Mutex's layout (a one-element array of lock and value). Each method is a short `lock` block, built by the checker (`atomic_method`). So every backend, the region analysis and the sharing check reuse the Mutex machinery, with no new LIR. Reads take the lock for the length of the copy. A lock-free box swap is the obvious later optimization: readers copying out of an immutable box, writers swapping a pointer to a new one.

## Package-level values

```ruby
# in package pkgs/settings
pub LEVEL = Atomic.new(Level.new(name: "info", n: 1))
pub HITS: Atomic[Int] = Atomic.new(0)
SEEN = Mutex[[Str]].new([])

pub def note(s: Str) {
  SEEN.lock { |xs| xs << s }
  HITS.add(1)
}

# elsewhere
settings.LEVEL.store(settings.Level.new(name: "debug", n: 2))
puts settings.HITS.load
```

- **Syntax** is a top-level constant's: `NAME = value`, `NAME: Type = value`, `pub NAME = ...`, read as `NAME` in its package and `pkg.NAME` elsewhere (only if `pub`). The main file may declare them too. A declaration is a package-level value when its declared type is `Atomic[..]` / `Mutex[..]`, or its value is `Atomic.new(..)` / `Atomic[T].new(..)` / `Mutex.new(..)` / `Mutex[T].new(..)`. The parser turns its value into a def, `__init_NAME`.
- **The name is a constant binding.** Assigning `NAME = ...` inside a def is an error that points at `store` / `lock`. What changes is the value inside.
- **Other non-constant top-level values are errors:** "`COUNTS` isn't a constant: a top-level value is computed at compile time, or is an `Atomic[T]` or a `Mutex[T]`", with an R11 note. A statement at a package's top level gets the same note.
- **Initialization** happens once, at program start, before main's first statement and before any task exists. The order follows Go's rule: a value is initialized after every value its initializer reads, through any chain of direct calls. Otherwise it goes in declaration order: each package after its imports, the main file last. A cycle is an error. An initializer that can fail is an error, since nothing at program start could handle it. Reads through interface method calls aren't followed (Go follows method values; alx can't name the implementor statically).
- **Typing.** An initializer is checked on first use of its value, or at the end, so every value is typed before any function reading it.
- **Visibility.** A main-file value is invisible to packages, which keep their own names.

## Memory

A package-level value is a global (`M::Global` / `LS::SetGlobal`, the machinery array constants already used). In the region analysis, a read of a global is the `Global` node. So a value stored through `store`, or under its `lock`, goes to the program region, and so does anything a lock block puts into the guarded value. It outlives every task. The initializer's result goes there too (`M::SetGlobal` flows its argument to `Global`).

- **Replaced values aren't freed.** An old value dropped by `store` stays in the program region. That's fine for the expected use: a handful of writes per program.
- **Fix found on the way.** A light frame (a function using a mark in its caller's region) never set its `dest` region when a frame allocation was nested inside a program-region one. A map key built inside a `lock` on a package-level Mutex hit this. The lowering now sets `dest` whenever some site is in the program region.

## Backends

C, JIT, the Rust oracle and wasm (both builds; the threaded one runs `pkgvars` on 4 threads) need nothing new: globals, locks and calls already existed. The oracle gained `PartialEq` for `Chan` (channel identity, which os/signal's table needs; C and JIT compared pointers already).

## std

| Package | Change |
|---|---|
| log | The standard logger is a package Mutex. `default` is a `Logger[io.Writer]` over it, and `set_output` / `set_flags` / `set_prefix` / `flags` / `prefix` / `writer` change or read it. Go's testPrint (TestAll) is translated through it. |
| math/rand | One global Rand behind a Mutex: the OS's randomness, 256 bytes per getentropy instead of 64 per call. Under GODEBUG `randseednop=0`, `seed` re-seeds it as Go 1.24's lockedSource; `randautoseed=0` starts it seeded with 1. TestSeedNop's three subtests are translated. |
| math/rand/v2 | The top-level functions share one ChaCha8, seeded once (was a system call per value). |
| os/signal | A handlers table. `stop(c)` works as Go's `Stop(c)`, and a second `notify` on a channel watches the union of its signals. |
| archive/zip | Package-level `register_compressor` / `register_decompressor`, consulted after a Writer's or Reader's own. Store, Deflate or a method registered twice panic. |
| net/rpc | `default_server`, plus the package-level `register`, `register_name`, `register_func`, `serve_conn`, `serve_codec`, `serve_request` and `accept`. Go's startServer is translated through it. `jsonrpc.serve_conn(conn)` serves it, as Go's does. |
| testing/iotest | The loggers log to `log.default`, and Go's logger tests redirect it, as written. |

## Tests

- **`pkgvars`** (S4) runs on JIT, C, ASan/UBSan, the Rust oracle and the browser (1 and 4 threads). It covers:
  - concurrent readers of an `Atomic[struct]` against a writer, with no torn reads;
  - Atomic of a struct, Str, `[Int]` and a Map: copies on load, swap, compare_and_swap;
  - a Mutex-held registry updated from ten tasks, in the main file and in a package;
  - cross-package `pkg.NAME`;
  - initialization order inside a file and across packages;
  - a Mutex of channels compared by `==`.
- **Negatives:**
  - `pkgvars.bad1`: a map at the top level;
  - `pkgvars.bad2`: an initialization cycle;
  - `pkgvars.bad3`: a private value read from another package;
  - `pkgvars.bad4`: assigning a package-level value.
- **`sync.bad4`** now checks `add` on an `Atomic[Str]`; it used to check that `Atomic[Str]` was refused.

## Not yet

- **Lock-free reads** for boxed atomics (above).
- **Leaked log lines.** Every line through a Logger over an `io.Writer` lands in the program region: 0.75 KB per line. This predates R11 (a Logger shared across tasks did the same). It shows more now, because the standard logger is shared. Cause: what the line flows into through the `write!` interface call is treated as kept by the logger.
- **Remaining #30 / #51 workarounds**, which could use R11 now:
  - crypto's RegisterHash;
  - crypto/rand's settable Reader;
  - the lazily built tables in crypto/des, ecdsa, ed25519, edwards25519 and nistec, and hpke;
  - os/user's cache;
  - math/big's divisor cache.
