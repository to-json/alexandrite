# R12, R13: Values that contain themselves

Decisions R12 and R13 (port-issues #2, #58, #71, #84, #92, #102, #108, #112, #114, #129). A type may now contain itself through indirection, and an interface's implementor may hold the interface:

```ruby
struct Node { name: Str; kids: [Node] }            # through a slice
struct Bst { key: Int; left: Bst?; right: Bst? }   # through optional fields
enum Json { Null; List(items: [Json]); Obj(fields: Map[Str, Json]) }
struct Server { routes: Map[Str, (Str) -> Str] }   # a route closure may capture its server
struct Upper { inner: Reader }                     # an Upper can itself be a Reader (R13)
```

What stays refused is a layout that would never end: a struct or enum holding itself *directly* (`struct Chain { next: Chain }`, `enum Expr { Add(l: Expr, r: Expr) }`, or the same through a tuple). The error names the path (`` `Expr` contains itself directly (Expr.Add(l)) ``) and suggests a slice, a map or an optional field.

Cyclic data (a node pointing back at its parent) is still impossible: values are copied, never shared by reference. Graphs with identity use `@T` handles into a `Pool` (R3).

## Types in the checker

`Ty` is a structural tree: a struct's type carries its fields. A self-mention can't be expanded, so it is a new `Ty::Rec(name)`:

- `struct Node { kids: [Node] }` is `Struct("Node", [("kids", Array(Rec("Node")))])`. The definitions of such types are kept by name (`tast::RECS`); `Ty::unrec` and `with_rec` reach them.
- **Equality:** `Rec(n)` equals the struct or enum named `n` (Ty's `PartialEq` and `Hash` are written by hand for that), so `[Node]` from a field and `[Node]` from an annotation are the same type.
- **Reaching a Rec unfolds it:** `mk` (every typed expression), `resolve`, instance arguments and generic bindings turn a top-level `Rec` back into its struct, so the rest of the checker sees ordinary structs.
- **Walks over types** that go through slices and maps (`printable`, `stringers`, `contains_int`, `shares`, ...) unfold each `Rec` at most once (`with_rec`, coinductive).
- **Generics:** an instance that mentions itself (`struct Tree[T] { kids: [Tree[T]] }`) gets `Rec("Tree[Int]")` while its fields are resolved. An instance that grows its type arguments forever (`Weird[[T]]` inside `Weird[T]`) is still an error.
- **Finite layout:** `inline_cycle` follows a recursive type's fields through everything held inline (struct and enum fields, tuples, fixed arrays, results; an optional only when it isn't a field) and refuses a cycle.

The old checks that refused these programs are gone: "`X` contains itself" (for indirect cycles), "X can't be a I: it holds a I value itself", and the self-containing-closure diagnostic (port-issues #2), since a closure type that contains itself is boxed.

## Layout (lowering)

A struct, enum, interface or closure type is *recursive* when its layout reaches itself: a struct through its fields, an interface through its implementors, a closure type through its lambdas' captures, `Error` through every error type. Lowering finds these by a reachability walk (`recursive`, memoized per program). A recursive type's LIR type is `LTy::Rec(i)`, a named tuple whose body is `LProgram::recs[i]`, and its self-mentions sit behind an array:

| What | Inline layout (unchanged) | Recursive |
|---|---|---|
| slice, map, pool, mutex, channel | already an array | the same |
| optional field `left: T?` leading back to its struct or enum | `(present, value)` | a box: a zero- or one-element array |
| interface value | `(tag, implementor 0, implementor 1, ...)` | `(tag, [implementor 0], [implementor 1], ...)` |
| closure value | `(tag, captures of lambda 0, ...)` | `(tag, [captures of lambda 0], ...)` |

- **Only the fields that need it are boxed.** An optional *field* is boxed when its payload leads back to the containing type without passing an array (or a boxed interface or closure). Optional locals, results, elements and map values keep the inline `(present, value)` layout. Field reads (`TupleGet`) unbox, and the constructors (`StructNew`, `VariantNew`) and field assignments box.
- **Interfaces pay only when recursive (R13).** An interface without an implementor that can reach it keeps today's layout and speed.
- **Boxes are never written through.** An optional, an interface value and a closure's captures change only by being replaced, so copies of a struct share its boxes. A `!` method called through a boxed interface value writes its receiver cell back as the new box.
- **The empty box is the zero value:** none, the first implementor's zero value, the first lambda with zero captures. So an all-zero struct (an omitted field) is still a valid value.

## Memory (R1)

Boxes are allocations like any other and follow the region placement:

- Constructors, interface conversions and lambdas were already allocation sites.
- An assignment to an optional field that may be boxed (`n.left = x`) is now one too. Its box flows to the assigned variable, so a node built in a call's frame and returned keeps its children alive. Before this, the box went into the frame and was freed under the returned tree.
- Copying (`dup`, compaction of owning maps and pools) is a generated function per recursive type (`__dup_recN`), so it terminates on trees.

A closure wrapping closures (an http.StripPrefix-style handler) runs its
body with its caller's region current. What a lambda's body stores into a
parameter's or a capture's storage goes to the region that storage lives
in, not the current one (port-issues #164; docs/notes/bang-calls.md).

A tree built and dropped in a loop stays in the loop's region: 300,000 iterations building two small trees each run in 2.7 MB.

## Comparing, printing, copying

These operations recurse over a value's type, which never ends inline for a recursive type. Each goes through a function instead:

- **`==`:** `struct_eq` on a recursive struct or enum calls the builtin `__eq[T](a, b)` (builtin.alx). Its own body compares one level inline; the checker marks that one comparison (`eq_top`). The recursion goes through function instances, which the checker already memoizes.
- **Interface values (#108):** `a == b` is `M::IfaceEq`: the same tag, then `__eq` of the two implementor values. Implementors are only known when checking ends (closed world, D12), so `iface_eq_instances` makes the instances then, to a fixpoint. `iface == concrete` converts the concrete side. Structs and slices holding interface values compare them field by field and element by element.
- **Printing:** `to_s` of a recursive type is a generated function (`__to_s_recN`) whose body is the inline printer.
- **Copying:** `deep_copy` of an `LTy::Rec` calls `__dup_recN`.

These helpers (`Lw::helper`) have no region of their own: they allocate in their caller's current region, as the inline code did.

## Backends

| Backend | Change |
|---|---|
| C | `RecN` is a named struct. Types are declared in an order that allows self-reference: every struct forward-declared, every slice type (`ALX_ARR_T`, which only needs its element declared), struct definitions after the structs they hold by value, then the slices' functions (`ALX_ARR_F`, which need complete elements). Tuples became named structs for the same reason. |
| JIT | `lay` of a `Rec` is its body's layout; field access unfolds `Rec`. |
| Rust oracle | `RecN` is a tuple struct (`#[derive(Clone, Default)] struct Rec0(Sl<Rec0>, ...)`), built as `Rec0(..)`; fields are `.0`, `.1` as for tuples. |
| wasm | as the JIT. |

Every backend sets `lir::set_recs(&p.recs)` before generating code.

## Tests

- `acceptance/cases/recursive.alx` (S5): a tree through a slice (build, walk, `dup`, `==`, print), a generic tree, a directory tree through a map, a binary search tree through optional fields, a 1000-node linked list built in a loop, a JSON-like enum, a server whose route closures capture it, middleware closures wrapping closures, test-like cleanups capturing their test (#112), and an optional closure field capturing its struct.
- `acceptance/cases/recursive_ifaces.alx` (S5): a Reader wrapping a Reader wrapping a Reader, a type switch and `as` on one, a zero boxed interface, MultiHandlers holding MultiHandlers and filters, a generic wrapper instantiated with the interface, `!` methods through a boxed interface, and `==` on interface values and on structs and slices holding them.
- `recursive.bad1`..`bad3`: a struct holding itself, an enum variant holding its enum, two structs holding each other through a tuple with an optional.
- `stdport_fixes.bad1` (a closure capturing its struct) and `l2fixes.bad1` (a reader holding a reader) were negative cases; both programs are valid now and are covered by the positive cases.

## Limits

- No cycles: values are trees. Use `@T` handles for graphs.
- `==`, printing and copying recurse on the stack: a 100,000-deep list compares with 100,000 nested calls.
- An optional inside a tuple field is inline, so `struct A { b: B }; struct B { p: (A?, Int) }` is refused; an optional field works.
- `Map` keys stay scalar, so recursive values aren't hashed.
