# R4: Captures, receivers, pools

Three pieces of the memory model that change what you can write. They are decisions R5 (captures), R7 (pointer receivers) and R3 (graphs).

## Lambdas capture variables (R5, replacing D16)

```ruby
count = 0
inc = -> { count += 1 }
inc(); inc(); inc()
puts count                   # 3

def counter -> (Int) -> Int {
  n = 0
  ->(by: Int) { n += by; n } # the lambda keeps `n`
}
```

- **What gets converted:** a variable a lambda captures that changes after capture (reassigned, pushed to, indexed into) becomes a one-element slice cell, in a pass over the checked program (`compiler/src/capture.rs`).
  - Slices share storage, so the function and every lambda see the same variable, and escaping lambdas keep it alive (the regions analysis sees the cell flow with the lambda).
  - Variables that never change after capture are still copied, which is indistinguishable and cheaper.
- **What still copies:** `spawn` bodies (a task boundary, so no data races) and generators.

## `!` methods through interfaces (R7)

```ruby
interface Writer {
  def write!(s: Str) -> Int
  def written -> Str
}
ws: [Writer] = [Buffer.new, Counter.new]
w.write!("hello")            # mutates the value inside the interface
```

- **Declaration:** interfaces can declare `!` methods, and implementors provide them.
- **Calls:** calling one on an interface value in a variable, field or element mutates it in place. This is Go's pointer receivers, which `io.Writer` and friends need.
- **Dispatch:** the call hands the implementor's method a cell of its own type, in the interface value's region, and writes it back.

## Pools and `@T` handles (R3)

```ruby
struct Node {
  key: Int
  left: @Node?               # a handle, not the node: recursion is fine
  right: @Node?
}
nodes = Pool[Node].new
h = nodes.add(Node.new(key: 50))   # @Node
nodes[h]                     # read (checked)
nodes[h] = Node.new(...)     # write
nodes.remove(h)              # Node? (leaves a tombstone)
for h, n in nodes { ... }    # live entries
```

- **Recursive types:** `@Node` names a type without containing it, so recursive and graph-shaped data can finally be declared.
- **Representation:** a pool is shared like a map, and freed with whatever region holds it. A handle is a slot index.
  - Reading a removed handle panics: "use of a removed pool handle".
  - The value for `nodes[h] = ...` is computed before the pool is touched, because computing it may add to the same pool and move its storage. The C sanitizer caught this.
- **Not yet:** compile-time branding, so that a handle can't be used with another pool of the same type.
