# R6: Sharing

Decision R4: tasks share mutable state only through channels, `Mutex[T]` and `Atomic[T]`. Unsynchronized sharing is a compile error, not a data race.

## Moves into tasks

A slice, a map, a pool, a closure, or anything holding one has storage another task could change. Once such a value goes into `spawn`, down a channel or into a `Mutex`, it belongs to the other side. Using it afterwards is an error, and so is using anything that shares its storage.

```ruby
results: [Int] = []
t = spawn { results << 1 }
results << 2        # error: `results` was moved into a task at 2:5, so the
                    # other task owns it now; using it here would share it
                    # without synchronization
```

| Pattern | Verdict |
|---|---|
| A fresh value per iteration (`part = [w, w * 2]; spawn { part.sum }`) | fine |
| A copy handed over (`copy = data.dup; spawn { copy.sum }; data << 4`) | fine |
| Sent, then reassigned (`ch << buf; buf = [2]`) | fine |
| A task's result taken back with `wait` | fine: it's ours again |
| A subslice of something sent (`view = data[1..]; ch << data; view[0]`) | error: `view` shares storage with `data` |
| The same slice captured on every loop iteration | error: each task would share it with the one before |
| A parameter handed to a task | error: it's the caller's storage; hand over `.dup` |

- **How it's checked** (`compiler/src/sharing.rs`): what shares storage comes from the region analysis's alias graph, in both directions, stopping at returns, globals, callers and mutexes. "Afterwards" is flow-sensitive:
  - branches merge;
  - loops and blocks run to a fixpoint (a block may run any number of times);
  - `break` and `next` carry their state to the right place;
  - assigning a variable again gives it fresh storage.
- **Graph fixes:**
  - a `Task` handle no longer aliases its captures;
  - a flat `.dup` (elements without storage) is fresh storage.

## Mutex[T]

```ruby
stats = Mutex.new(Stats.new(hits: 0, names: []))
spawn {
  stats.lock { |s|
    s.hits += 1
    s.names << "w#{w}"
  }
}
total = stats.lock { |s| s.hits }       # the block's value is copied out
```

- **`lock` runs the block holding the lock.** The block gets the value; changes to it, reassignment included, are written back when the block ends.
- **Leaving early is a compile error,** since it would keep the lock held. That covers `return`, `~`, `fail`, and `break`/`next` out of the block (loops inside it are fine).
- **Nothing outside the block may keep a reference into the guarded value** (`keep = xs` is an error). The block's value is deep-copied out instead.
- **`Mutex.new(v)` moves `v` in.** Using `v` afterwards is the same error as for tasks.
- **A lock is a scheduler wait like a full channel,** so a self-deadlock reports "all tasks are asleep: deadlock".

## Atomic[T]

`Atomic.new(0)` or `Atomic.new(false)`, with `load`, `store(v)`, `add(n)` (Int; gives the new value), `swap(v)` (gives the old value) and `compare_and_swap(old, new)`. All are sequentially consistent. Anything else goes in a `Mutex`.

## Backends

| Backend | Lock | Atomics |
|---|---|---|
| C | runtime `alx_lock`/`alx_unlock` | `__atomic` builtins |
| JIT | through shims | Cranelift `atomic_*` instructions |
| Rust oracle | `Mutex<bool>` + `Condvar` | `AtomicI64` |
| Browser | refused, with tasks and channels | refused |

New LIR: `LTy::Lock`/`Atomic`, `LockNew`, `Lock`/`Unlock`, `AtomicNew`/`Load`/`Store`/`Rmw`/`Cas`.

## Tests

- `sharing.alx` and `sync.alx` run on every backend, ASan included.
- Eight negative cases (`sharing.bad1-4`, `sync.bad1-4`).
- Acceptance: **190 of 190 checks pass.**

## Not yet

- **Read-only sharing.** Workers reading one big slice must each get a `.dup`. A frozen, immutable share is the likely fix.
- **`.dup` is shallow.** Nested slices inside a dup still share, and the check doesn't see it.
- **Unbounded growth.** What a task stores under a lock lives in the program region and isn't compacted. The R3 compaction could apply at unlock.
- **Locking cost.** Locks go through the scheduler's single lock: correct, not fast.

## Later: interface values (port-issues #270, D88)

Whether an interface value shares storage comes from its implementors (closed world), which made the hand-over check depend on the whole program: os/exec's context watcher (`cx = c; spawn { ... cx.done ... }`) compiled under `alx test std/os/exec` and failed in any program that never made a Context, because an interface without implementors was missing from the program's implementor table and counted as unknown, so as sharing.

- **An interface without implementors doesn't share:** no value of it exists.
- **`#[shareable]` before an interface** makes the judgement a contract: its values never count as sharing, whatever the program converts to it, and converting a type that holds a slice, map, pool, closure or sharing interface value outside a Mutex, an Atomic or a channel is an error at the conversion (`shareable.bad1`). context.Context is `#[shareable]`, so library code hands Contexts to tasks without `.dup`.
