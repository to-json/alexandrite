# R7: Explain

Decision R8: memory placement stays silent, and `alx explain mem` shows it on demand. It lists every allocation site of the program, the region the value lives in, and why.

```
$ alx explain mem explain.alx
(top level)  explain.alx
  2:14    []                                 frame: freed when the program ends
  6:10    "line #{i}"                        frame: freed when the program ends  << every iteration: piles up until then
  7:3     cache[i % 10] = "value #{i}"       `cache`'s own region: compacted at the loop at 5:7
  7:19    "value #{i}"                       `cache`'s own region: compacted at the loop at 5:7
  9:5     log << line                        frame: freed when the program ends  << every iteration: piles up until then
  11:7    spawn { "task #{i}" }              iteration of the loop at 5:7: freed each time round
  11:15   "task #{i}"                        program region, never freed: it reaches `spawn { "task #{i}" }` at 11:7  << every iteration: grows without bound
  12:8    t.wait.unwrap                      iteration of the loop at 5:7: freed each time round

1 allocation site(s) in the program region; 3 site(s) inside loops that pile up
```

## What it says

| Place | Meaning |
|---|---|
| **frame** | freed when the function returns |
| **iteration of the loop at L:C** | freed every time round (R1) |
| **the caller's region** | it's the result (R1) |
| **the region of `p`** | stored into a parameter's storage (R2) |
| **`c`'s own region** | an owning container, compacted at the loop (R3) |
| **program region, never freed** | with the expression that sent it there: a `spawn`, a channel send, a global, or a function that keeps it |

The "every iteration" marks are the old plan's hot-loop lint, without refcounts. A site inside a loop whose value lives in the frame or the program region accumulates: until the function returns, or forever. The marks list exactly those sites.

## How

- **Reasons.** The region analysis now records, for each node it sends to the program region, the expression responsible. The explainer walks from an allocation site to the first node with a reason.
- **Loop positions** are recorded in the analysis too: a `while`'s condition, or the iterating call.
- **No new analysis.** The explainer reuses the placement the compiler computes for lowering, so what it prints is what the program does.
- **Fewer phantom sites.** Values without storage (Ints, atomics, Unit) aren't listed, except stores, whose growth allocates.

## Tests

- An R7 acceptance check runs `alx explain mem` on `mem/explain.alx` and checks the four kinds of answer and the summary line.
- Acceptance: **191 of 191 checks pass.**

## Not yet

- **Program-region reasons through calls.** A function that keeps its argument shows "it reaches `f(x)` at L:C", not the store inside `f`.
- **Opt-in warnings.** No lint mode turns the marks into warnings (`--strict` could).
