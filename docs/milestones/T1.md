# T1: Scripting

Shell scripts and the repository's Python tooling, in alexandrite. Three pieces:

- **Command literals:** backticks build a command; alx parses it, no `/bin/sh`.
- **`os/exec`:** Go's package, plus pipelines, redirects and measurements.
- **`sh`:** files, globs, directories, environment, script conveniences.

The acceptance harness, the benchmark runner, the doc-site builder and the sort-kernel generator are now alx programs. Python is gone from the repository outside `probes/` (historical experiments).

```ruby
import "sh"

for f in sh.~glob("src/**/*.c") {
  `cc -O2 -c #{f} -o build/#{path.base(f)}.o`.~run   # f with spaces is one argument
}
n = `grep -c TODO #{*sh.~glob("src/**/*.c")} | wc -l`.~output
`make 2>&1 > build.log`.~run                          # redirects, left to right
sh.in_dir("build") { `tar czf out.tgz .`.~run }       # back to where we were after
sh.parallel(sh.~glob("img/*.png"), 8) { |f| `optipng -quiet #{f}`.~run }
st = `./server --selftest`.~capture.state              # exit code, CPU time, peak RSS
```

## Command literals

- **Words:** split on blanks.
  - `'...'` is literal.
  - `"..."` takes `\" \\ \` \$` escapes and `#{}`.
  - `\c` outside quotes is `c`.
- **Interpolation:**
  - `#{x}` is part of one argument, never split or re-parsed, so there is no quoting to get wrong and no injection.
  - `#{*xs}` splices a `[Str]` as separate arguments.
- **Operators:** `|`, `<`, `>`, `>>`, `2>`, `2>>`, `&>`, `2>&1`, `>&2`. Applied left to right, as in sh: `2>&1 > f` sends stderr to the old stdout.
- **What isn't there is an error,** with a hint:
  - globs (`*` `?` `[`): use `sh.glob`;
  - variables (`$`): interpolate;
  - `&&` `||` `;`: use the language's control flow;
  - `&`: use a task;
  - subshells.
- **Desugaring:** the literal becomes `os/exec.from_literal(groups, kinds)`, a `Cmd` value. The file gets a hidden `import "os/exec"`.
- **Running it:** nothing runs until `.~run` / `.~output` / `.~capture` / `.~exec`. A literal's `run` shows the command's output (`passthrough`); Go's `Run` discards it.
- **Failure:**
  - A nonzero exit is an `ExecError.Exit`, carrying the command line, the status and the stderr text (like `set -e`).
  - `ALX_EXEC_NOFAIL=1` in the environment, or `c.check = false`, makes it return the status instead.
  - Pipelines fail if any stage fails (`pipefail`), except an earlier stage killed by SIGPIPE (`yes | head`).

## `os/exec`

- **Go's API:** `command(name, args)`, `run`, `output`, `combined_output`, `look_path`, `ProcessState`, `ExitError`. `Cmd` is a value: fields `dir`, `env` (none = inherit), `stdin` (text).
- **Additions:**
  - `capture`: stdout, stderr and the state, without failing on a nonzero exit.
  - `pipe(other)`.
  - `exec`: replaces the process (Go's `syscall.Exec`).
  - Each `ProcessState` has `user_ns` / `sys_ns`, `max_rss` (peak resident bytes, from `wait4`) and `wall_ns`.
- **Runtime:**
  - New shims: `alx_sys_spawn` (posix_spawnp with dup2 and chdir), `alx_sys_wait` (wait4 + rusage), `alx_sys_pipe`, `alx_sys_poll2`, `alx_sys_exec`. All backends have them: the C runtime, the JIT symbol table, and the Rust oracle through `std::process`.
  - stdout and stderr are drained together, so large outputs on both don't deadlock.
  - `stdin` text is written by a task, so any size works.
- **A relative program path with a slash** (`.alx-cache/x-rel`) is relative to `dir`, as in Go.

## Language changes it needed

- **Fallible lambdas and blocks.** A lambda of type `(..) -> ~T` may use `~` and `fail`, like a fallible def. A block passed to such a parameter is one: `sh.in_dir("x") { `make`.~run }`. Before this, `~` inside any lambda was an error.
- **`[T] + [T]`** concatenates into a new slice (Ruby's `Array#+`, Go's `append(a, b...)`).
- **`f.dup` on a function value** copies its captures deeply, so it can go to a task (the sharing checker suggested it, but it didn't exist).
- **Fixed: pushes inside lambdas were lost when the variable was declared with a type.** `out: [Str] = []` followed by `twice { out << x }` left `out` empty: typed declarations weren't marked as user variables, so captures-by-reference (R5) skipped them. They also warn when unused now, like other locals.

## First memory comparison

`bench.alx --mem` reports each runner's peak resident set (from `wait4`).

- **Project Euler cases:** alx release has the smallest peak everywhere (about 1.2 MiB, against Go's 3.8 and Ruby's 14), except pe014 (16.8 vs Go 12.5: two million-element arrays where Go keeps one).
- **Three allocation-heavy cases added for this** (with Go and Ruby ports; not yet in the harness's check groups):

| case | alx-run | alx-rel | Go | Ruby | Ruby YJIT | time alx-rel / Go |
|---|---|---|---|---|---|---|
| `bintrees` (pools, depth 14) | 20.0 | 15.0 | 10.5 | 16.7 | 17.2 | 132 / 30 ms |
| `strchurn` (200k lines, join, split) | 87.5 | 82.8 | 27.6 | 67.4 | 64.8 | 54 / 40 ms |
| `wordfreq` (1M words, Map) | 60.0 | 52.4 | 8.7 | 18.8 | 19.4 | 131 / 34 ms |

(peak MiB)

What `alx explain mem` says:

- **wordfreq:** passing `pairs` to `slices.sort_func` with a block sends everything that reaches it to the program region: the map, and through it every `word(...)` string built in the 1M-iteration loop. Every word ever made stays alive.
- **strchurn:** `line.split(" ")` in the inner loop piles up in the frame instead of being freed each iteration. (`split`'s pieces share the original, as in Go.)
- **bintrees:** closest to Go. The stretch tree stays until the program ends, and pools grow by doubling.

## Speed pass on the allocation-heavy cases

Release builds, ms (Go prebuilt alongside):

| case | before | after | Go | peak MiB after (Go) |
|---|---|---|---|---|
| `bintrees` | 132 | 23.6 | 25.9 | 15.2 (10.8) |
| `strchurn` | 54 | 18.9 | 37.0 | 82.8 (36.6) |
| `wordfreq` | 131 | 37.6 | 32.0 | 5.7 (9.4) |

Project Euler and nbody are unchanged or faster. `alx run` (JIT) keeps out-of-line calls for region switches, so it gains less (wordfreq 85 ms).

### Regions
- **Idle regions aren't made.** A post-pass over the LIR follows which region is current through every enter, use and restore, and drops a call's frame or a loop's iteration region if nothing can allocate while it's current. `make` and `check` in bintrees no longer enter a region per call.
- **Idle switches are dropped.** A region switch around code that allocates nothing (a value built in place) goes away.
- **Cheaper iteration regions.** An iteration region is a mark and reset on the region current at the loop (as light frames are for calls) when, while it's open, nothing allocates into another existing region and no call could store through its arguments. Otherwise its enter and exit are inline in the common case: a pooled region struct that kept its one chunk.
- **Fewer thread-local lookups.** The hot runtime thread-locals live in one struct (`alx_tls`): on macOS each thread-local costs an address lookup per function, so this is one lookup instead of five. `alx_region_cur`/`use`/`set`/`bytes` are inline, and `alx_region_of` caches its last 1 MB granule.

### Escapes
- **Clean function types.** A call through a function value no longer sends its arguments to the program region when every lambda of that function type keeps its parameters to itself. This is what `slices.sort_func(pairs) { ... }` needed.
- **Map keys.** A `Str` key is copied when it's inserted (strings are immutable, so it can't be told apart), so the key passed in doesn't have to outlive the call. wordfreq's million temporary words are freed each iteration: 52 MiB → 5.7.

### Strings and maps
- **`s += x` appends in place.** When `s` is the most recent concatenation and ends at the bump pointer, the new bytes go after it: building a string piece by piece is linear. `"" + x` is `x`.
- **`split`** finds separators with `memchr` instead of a `memcmp` at every byte (strchurn 49 → 19 ms).
- **Short string compares are inline.**
- **Maps remember the last entry found.** `m[k] = f(m[k])` hashes once.
- **Deleted entries leave a tombstone in the slot table,** so lookups don't read the `live` array.
