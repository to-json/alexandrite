# tree-sitter-alexandrite

A [tree-sitter](https://tree-sitter.github.io) grammar for alexandrite (`.alx`), with highlight, locals and injection queries.

The compiler's hand-written parser (`compiler/src/lexer.rs`, `parser.rs`) defines the language; this grammar follows it. When you change the syntax, update the grammar in the same change. The acceptance group `TS` checks that they agree.

## Layout

- `grammar.js`: the grammar.
- `src/scanner.c`: the external scanner, for what a context-free grammar can't decide:
  - a newline ends a statement only where one may end, and a line starting with `.`, `?.`, `else` or `elsif` continues the previous one (comment lines may sit between);
  - in a condition (`if`, `while`, `for`, `case`), a `{` after a callee starts a block only when `|` follows (`if xs.any? { |x| x > 1 } {`);
  - a `?` or `!` belongs to a name (`empty?`, `move!`) except in `x?.f`, `x?:` and `a!= b`;
  - `puts -x` passes `-x` to `puts` (a space before the `-`, none after), while `a - x` and `a-x` subtract;
  - heredocs: `<<~ID` and `<<~"ID"` (escapes and `#{}`), `<<~'ID'` (raw), several per line. A body is a `heredoc_body` node next to the statement that starts it.
- `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/`: generated by `tree-sitter generate`. They're committed; regenerate them whenever `grammar.js` changes.
- `queries/`: `highlights.scm`, `locals.scm`, `injections.scm`.
- `test/corpus/*.txt`: parse tests, one file per area (declarations, statements, expressions, types, strings, sugar). `test/highlight/`: highlight assertions.

## Commands

```sh
cd tree-sitter-alexandrite
tree-sitter generate          # after editing grammar.js
tree-sitter test              # corpus and highlight tests
tree-sitter parse -p . f.alx  # show a file's tree
target/release/alx run acceptance/run.alx -k TS   # from the repo root: the parity check
```

`tree-sitter test --update` rewrites expected trees from the current output. Review every changed tree before you keep it. It also turns `\uXXXX` escapes in test inputs into the characters they name, so restore those by hand.

## Where the trees differ from the compiler

The grammar has no symbol table, so a few readings depend on spelling where the compiler looks at scope:

- `x -1` with a space before the `-` and none after reads as the command call `x(-1)`. The compiler reads it as a subtraction when `x` is a local. Write `x - 1`.
- `~f(x).g` is `~` applied to the whole chain `f(x).g`. The compiler applies `~` to the first call, `f(x)`, and then calls `.g` on the result.
- The grammar accepts more than the compiler does. A keyword where the compiler's parser rejects one, such as `x = fail` or `x = return 1`, parses here as an ordinary name.
